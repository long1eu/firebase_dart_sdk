# Remote Config parity with the JS, Android, iOS and C++ SDKs

This document compares the public API and the behaviour of the Remote Config clients of four official SDKs with `firebase_remote_config_dart` (`firebase_remote_config/firebase_remote_config_dart`), feature by feature:

- **JS**: `packages/remote-config` of firebase-js-sdk at `a086865`. It is the reference for the protocol.
- **Android**: `firebase-config` of firebase-android-sdk at `2cfdd03`. It is the reference for throttling, activation, value conversion and realtime.
- **iOS**: `FirebaseRemoteConfig` of firebase-ios-sdk at `cef246f`.
- **C++**: `remote_config` of firebase-cpp-sdk at `09d2e7a`. Its desktop code (`CD:`) speaks REST itself; the mobile wrappers delegate to the native SDKs.
- **Dart**: `firebase_remote_config_dart` 0.1.0 and the `FirebaseRemoteConfig` it describes. The Dart column states the behaviour of the package; it was checked against the code. To read a row quickly, start with the Dart and Notes columns.

The four SDKs were read as source clones on 2026-11-27, from GitHub only; their code was read, not run. Line numbers will drift. The Installations client that Remote Config depends on has its own document: [installations_parity.md](installations_parity.md). The reasons for each departure from upstream, the alternative that was rejected and the test that pins it are in [remote_config_decisions.md](remote_config_decisions.md); the notes below name them as D1 to D14.

The Status column compares the Dart behaviour with the SDK named in the cell, or with all of them when it names none:

- **same**: the behaviour of the SDK named in the cell, or of all four
- **different**: a deliberate change, with the reason in the notes
- **missing**: not in 0.1.0; the notes say whether it is planned
- **won't do**: the notes give the reason

Path shorthand:

- `J:` is JS `packages/remote-config/src`, and `JU:` is `packages/util/src`.
- `A:` is Android `firebase-config/src/main/java/com/google/firebase/remoteconfig`, and `AI:` is `A:internal`.
- `I:` is iOS `FirebaseRemoteConfig/Sources`, and `IH:` is its public `FIRRemoteConfig.h`.
- `C:` is C++ `remote_config/src`, `CH:` is its public header and `CD:` is `C:desktop`.

## What the Dart packages are for

The C++ SDK's desktop Remote Config sends a new random installation id and a random token with every fetch (`CD:rest.cc:77-105`) and has no realtime updates. FlutterFire's `firebase_remote_config` says that realtime updates "are not yet supported on Windows and other desktop platforms". The JS SDK runs only in a browser. `firebase_remote_config_dart` is a Remote Config client for the Dart VM (macOS, Windows, Linux) and the web (dart2js, dart2wasm), with a real, persisted installation from [`firebase_installations_dart`](installations_parity.md), realtime updates and no Flutter dependency.
